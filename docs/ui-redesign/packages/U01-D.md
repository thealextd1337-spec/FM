## Freigegebener Vertrag

I00 markiert vorhandene `.v62-table` mit `data-fl-competition-id` und zuordenbare Kalender-/Ergebnisknoten mit `data-fl-fixture-id`. Keine aus Namen erratenen Verknüpfungen.

```js
competitions: {
  tables: [{id, rows:[{clubId,wins,draws,losses,goalsFor,goalsAgainst}]}],
  report: null | {
    id, title, contextLabel,
    home:{id,name}, away:{id,name}, scoreLabel, penaltiesLabel:null,
    teamStats:null | [{label,home,away}],
    events:null | [{minuteLabel,text}],
    lineups:null | {home:[{id,name}],away:[{id,name}]},
    substitutions:null | [{minuteLabel,teamLabel,out:{id,name},in:{id,name}}],
    players:null | [{id,name,teamLabel,stats:[{label,value}]}],
    awards:null | [{kind,label,playerId}]
  }
}
```

Alle Texte sind fertige Anzeigewerte; keine Fähigkeiten/Rohspielerobjekte. `null` bedeutet nicht erfasst, `[]` erfasst ohne Ereignis. Einzelfakten verwenden null für fehlende Messwerte, niemals erfundene Null. Allgemeine gespeicherte Spielerfakten: Minuten, Tore, Vorlagen, Schüsse, Fouls, Elfmeter verwandelt/verschossen, zu null/Gegentore, Note, Tacklingversuche/gewonnene Tacklings – jeweils nur falls aufgezeichnet. Titel/Awards nur über gespeicherte Honours oder `manOfMatchPid`.

Produzenten: `v64FinishFixture` (`world-match-v64.js:277`) schreibt `score/starters/tacticChanges/substitutions/events/players` und optional `ballAccounting`. `v64ArchiveSeason` (`:301`) bewahrt `fixture.result`, `lineups` und `switches`, löscht `matchRecord/plan`. Keine Wiederherstellung gelöschter Statistiken aus Karriereaggregaten. `v65WorldReport` enthält live weitere Teamdaten, wird aber nicht rückwirkend für alte Partien aufgerufen.

Aktionen `actions.openReport(fixtureId)` und `actions.closeReport()` führen ausschließlich I00s flüchtige Berichtauswahl und Refresh aus. U01-D rendert den bereitgestellten nativen Datendialog; Öffnung/Schließen verändert keine Karriere. Profilwege im Body-Dialog verwenden `actions.openPlayer(pid,button)`, da die bisherige Weltdelegation den Dialog nicht erreicht. Schließen/Escape stellt Fokus auf den Kalender-/Ergebnisauslöser zurück. Handler pro Root einmal, idempotent; keine Rohglobals oder neue Fachcontroller. Der Enhancer arbeitet ausschließlich auf `.fl-content`, nicht auf Profil-/Berichtdialogen. Cleanup entfernt Listener und eigenen Dialog.

Der Produzent berücksichtigt explizit gespeicherte `manOfMatchPid` (fehlend → null, explizit ohne Vergabe → leere Liste), vorhandene vollständige Schuss-/Foulwerte beider Mannschaften und ihre Erfassungslücken, Eigentore/Freistoßtore, vorhandene Nachspielzeitbeschriftungen und gespeicherte Gesamtergebnisse. Die Ansicht errechnet keine fehlenden Matchwerte.
